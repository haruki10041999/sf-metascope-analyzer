## 変更したこと

- 標準オブジェクト（[standardObjects.ts](../../../src/analyzer/processor/Apex/semantic/standardObjects.ts)）
    - Account の項目の例から `AccountScore` を外した。Object Reference の Account の項目の表になく、PDF 全体にも出てこない。
    - `AccountScore`（API 61.0）・`AccountSource`（API 24.0）の導入版の記載を消した。Object Reference に導入版の記載がない。
    - そのあと、項目の例（`fieldExamples`）と項目の型（`ApexStandardObjectField`）を、どのコードも使っていないので一覧から消した。一覧はオブジェクトの名前だけを持ち、スキルも項目の情報を足さない（利用者の決定）。項目の照合結果は [apex-standard-examples.md](../apex-standard-examples.md) に残す。
    - 依存関係のグラフ（[graph.ts](../../../src/analyzer/processor/dependency/graph.ts)）が別に持っていた同じ一覧を、この一覧に 1 本化した（グラフに残したのは汎用の `SObject` だけ）。
- 資料: [apex-standard-examples.md](../apex-standard-examples.md) の Account の行、[apex-standard-reference.md](../apex-standard-reference.md) に「照合の記録」を追加。

Apex の標準型（2,504 件・81 名前空間）、メソッド名の例、`String.equals(secondString)` の非推奨、標準オブジェクト 50 件、package.xml の種類名 56 件は、資料と食い違いがなかった。

## リリースノートの要点

## 判断が要ること

- `toPackageXml` の既定の API バージョンは `'62.0'`（最新は 68.0）。古い組織への配置で使えるので誤りではないが、既定を新しくするか、`sfdx-project.json` の `sourceApiVersion` を必ず渡すようにするかを決める。
